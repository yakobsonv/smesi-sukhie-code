## Как работать с кодом

```
npm ci                               # строго по package-lock.json (npm install его переписывает)
npm run dev                          # локально
python3 -I scripts/build_positions.py   # пересобрать данные каталога (после правки data/)
npm run build                        # сборка — должна пройти без ошибок (17 страниц)
npx astro check                      # проверка типов — 0 ошибок
git push origin main                 # выкладка: Vercel собирает и выкладывает сам
```

Папку `.vercel/` ни в какие другие репозитории не копировать — выкладка уйдёт не в тот проект. В `.vercelignore`
закрыты от выгрузки только корневые `/data`, `/scripts`, `/recon`, `/docs`: правило без слэша однажды выкинуло и `src/data`,
и удалённая сборка упала.

## Правила (обязательно)

1. **Назначение и характеристики — дословно по сайту производителя.** Ничего не досочинять и своих технических
   советов не писать («что выбрать», «когда клей, а когда раствор» — это факт производителя). Адрес карточки
   производителя и дата сверки хранятся в данных (`src`, `checked`) и **на страницу не выводятся**. Ссылки наружу —
   только на PDF-техкарты Dauer.
2. **Цены — из магазина tk-sm.ru** («да» Влада 11.10). Нет цены в магазине — «Цену назовём по телефону».
3. **Только сухие смеси.** Не сухие позиции магазина сборщик отбрасывает сам: тип в `records.json`, решение
   `not_dry_mix` в `mapping.json`.
4. **Слово «дилер» не писать** (Влад 11.10).
5. **Фото упаковок с сайтов производителей можно** (Влад 11.10). Каждый кадр смотреть глазами. Маленький исходник
   не растягивать (сборщик только уменьшает до 480 px). У Perel RodStone «Адгезив» и «Основа» фото нет намеренно:
   на карточке производителя там газон, а не упаковка.
6. **Подписи вариантов** (фасовка, цвет, «зимняя версия») строит скрипт из названия позиции в магазине. Раньше
   их писали вручную, и на страницу просочились служебные пометки — вручную не вписывать.
7. **Позиция магазина без карточки у производителя на сайт не ставится:** фактов нет. Таких сейчас 41, список в
   «Сухие смеси — сборка этапа 1 (11.10.2026)».
8. **Приём заявок не подключён** (слово Влада): связь по телефону, форм нет. Метрику до домена не ставить.
9. **Всё, что окно рисует скриптом** (строки вариантов и характеристик), стилизуется через `:global()` внутри
   родителя. Иначе стили Astro до этих узлов не доходят: 11.10 цена так слиплась с вариантом.
10. Служебных фраз для нас на страницах быть не должно.
11. Правило слияния из плана: если в разделе меньше 5 позиций, он становится секцией соседнего. Так «Затирка» ушла
    в «Плиточный клей», а «Стяжка» — в «Наливной пол».

## Как добавить или обновить позиции

1. Новый ассортимент магазина: обход tk-sm.ru — `recon/scripts/crawl_tksm.py` (curl без JS, в один поток с паузой
   0,3 с; страницы в cp1251). Он сохраняет только страницы и `tksm/index.json` (адрес, код, заголовок).
   ⚠️ Разбор страниц в `data/tksm_items.json` (поля id, url, name, brand_seg, section, sub, price, pack, brand; 419
   записей на 11.10) скриптом в репозитории не оформлен — 11.10 его делал агент. Обновлять цены и ассортимент —
   только по задаче от Влада: сначала написать разборщик, сверить его вывод с текущим `tksm_items.json`, потом менять.
2. Для новой позиции дописать в `data/mapping.json` связку с товаром производителя (`series_key` из `records.json`).
   Решение: `same_product` или `renamed_same_product` — и обязательно основание.
   - Совпасть должен **код модели** (AC12 ≠ AC121, PG26 ≠ PG26/1), а не смысл названия.
   - Сборщик сам отбраковывает связки `same_product`, где код не совпал: смотреть `problems` в
     `data/build_report.json`. Связки `renamed_same_product` он пропускает без проверки — их сверять глазами.
3. Товара нет в `records.json` — сначала дословный разбор его карточки у производителя, тем же способом, что
   в `recon/`. Для Стройбриг и Promix — запись в `other_brands.json` плюс сохранённый текст страницы.
4. `python3 -I scripts/build_positions.py` → `npm run build` → проверка (ниже) → выкладка.
